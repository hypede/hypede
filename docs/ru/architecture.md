# Архитектура HypeDE 1.0

HypeDE не заменяет GNOME, а надстраивается над ним так же, как это делает
Ubuntu со своим сеансом: собственный **режим оболочки**, собственное
**расширение** и собственные **приложения**. Пакеты GNOME и KDE остаются
нетронутыми и обновляются дистрибутивом как обычно.

```
экран входа ──► hypede.desktop ──► gnome-session --session=hypede
                                        │
                        gnome-session@hypede.target (systemd)
                          ├─ gnome-session-services.target  (gsd-*, порталы…)
                          └─ org.gnome.Shell@hypede.service → gnome-shell --mode=hypede
                                        │
                     /usr/share/gnome-shell/modes/hypede.json
                          ├─ панель: только дата и статус справа
                          ├─ colorScheme: prefer-light
                          └─ enabledExtensions: hypede-shell@hypede.dev
```

`XDG_CURRENT_DESKTOP` в сеансе — `HypeDE:GNOME`. Благодаря этому
значения по умолчанию из `90_hypede.gschema.override` (секции с суффиксом
`:HypeDE`) действуют только внутри HypeDE, а порталы и приложения,
которые ищут «GNOME», по-прежнему его находят.

## Оболочка: расширение `hypede-shell`

| Модуль | Что делает |
|---|---|
| `shelf.js` | Переносит верхнюю панель GNOME к нижнему краю (перехватывает `LayoutManager._updateBoxes`), разворачивает меню индикаторов вверх, добавляет значки приложений, дату и время в трей, автоскрытие. Кнопка шестерёнки в быстрых настройках открывает «Настройки» HypeDE. |
| `launcher.js` | Кнопка-кольцо и «пузырь» лаунчера — это `PanelMenu.Button` с собственным содержимым меню, поэтому клавиатура, Escape и клики мимо работают как у всех меню GNOME. |
| `calculator.js` | Разбор арифметики рекурсивным спуском (без `eval`). |
| `recent.js` | Чтение `recently-used.xbel` для «Продолжить с того же места». |
| `overview.js` | Super → лаунчер, обзор без дока и строки поиска, старт сеанса сразу на рабочем столе. |
| `notifications.js` | Баннеры уведомлений в правом нижнем углу, появление снизу вверх. |

Почему панель, а не своя полка с нуля: панель GNOME уже умеет резервировать
место под окна (strut), прятаться в полноэкранном режиме, работать с
клавиатуры и держать меню всех системных индикаторов (сеть, звук,
Bluetooth, питание, запись экрана). Всё это продолжает работать, а
расширениям сторонних авторов, добавляющим индикаторы, ничего менять не нужно.

Стили генерируются `tools/gen-shell-css.py` из одного шаблона в две палитры
(светлую и тёмную); GNOME сам выбирает файл по системной схеме. Цвет
акцента берётся из `-st-accent-color`, поэтому выбор акцента в «Настройках»
перекрашивает и полку.

## «Настройки»: модули KDE в интерфейсе Chrome OS

```
MainWindow (QWidget, без системной рамки)
 ├─ QQuickWidget — весь интерфейс на QML: заголовок с поиском, меню, карточки
 └─ контейнер модуля (QWidget) — лежит поверх QML ровно в «окне» карточки
      └─ KCModuleLoader::loadModule(...) — модуль KDE, как в kcmshell6
```

* `KcmHost` загружает модуль по id (`kcm_pulseaudio`, `kcm_networkmanagement`…),
  ищет его во всех каталогах Plasma 6 и кладёт его виджет в контейнер.
  `KCModuleLoader` одинаково работает и с QML-модулями, и со старыми на
  виджетах, поэтому встраиваются оба вида.
* `GSettingsObject` — мост QML ↔ GSettings для разделов, которыми в
  сеансе управляет GNOME.
* `System` — D-Bus: power-profiles-daemon, NetworkManager (Wi-Fi),
  timedated (синхронизация времени), версия GNOME Shell.
* Палитра модулей KDE берётся из цветовых схем `HypeDE Light/Dark`
  (светлые фоны и синий акцент Chrome OS) и переключается вместе с
  темой GNOME.
* Каталог разделов (`qml/Catalog.qml`) — декларативный: строка описывается
  объектом `{type, schema, key, …}`. По этому же каталогу работает поиск.

## «Файлы»

```
Adw.OverlaySplitView
 ├─ Sidebar           места, закладки GTK, устройства (Gio.VolumeMonitor)
 └─ ToolbarView
     ├─ HeaderBar     назад/вперёд, PathBar (крошки ↔ поле адреса), вид, поиск
     ├─ Adw.TabBar    вкладки (COSMIC)
     ├─ SearchBar     рекурсивный поиск в фоне
     └─ Adw.TabView → FolderView (на каждую вкладку)  +  DetailsPane (COSMIC)
```

`FolderView` собран из готовых моделей GTK: `Gtk.DirectoryList` (чтение
каталога асинхронно, слежение за изменениями) → фильтр скрытых →
сортировка «папки сначала» → `Gtk.MultiSelection`, и две вьюхи на одной
модели — `Gtk.GridView` и `Gtk.ColumnView`. Файловые операции идут в
фоновых потоках через Gio (понимают `trash://`, `sftp://`, `smb://`), а
результат сообщается тостом с кнопкой «Отменить».
