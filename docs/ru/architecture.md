# Архитектура HypeDE

HypeDE не заменяет GNOME, а надстраивается над ним так же, как это делает
Ubuntu со своим сеансом: собственный **режим оболочки**, собственное
**расширение** и собственные **приложения**. Пакеты GNOME и KDE остаются
нетронутыми и обновляются дистрибутивом как обычно.

```
экран входа ──► hypede.desktop ──► /usr/lib/hypede/hypede-session
                                        │  DCONF_PROFILE=hypede (своя база настроек)
                                        │  XDG_DATA_DIRS += /usr/share/hypede/shell
                                        │  перенос настроек из GNOME при первом входе
                                        ▼
                               gnome-session --session=hypede
                                        │
                        gnome-session@hypede.target (systemd)
                          ├─ только нужные gsd-* (питание, клавиши, звук, ночной режим…)
                          ├─ необязательные службы — по dev.hypede.session optional-services
                          ├─ hypede-session.service (убирает переменные при выходе)
                          └─ org.gnome.Shell@hypede.service → gnome-shell --mode=hypede
                                        │
               /usr/share/hypede/shell/gnome-shell/modes/hypede.json
                          ├─ панель: только дата и статус справа
                          ├─ colorScheme: prefer-light
                          └─ enabledExtensions: hypede-shell@hypede.dev
```

Каталог `/usr/share/hypede/shell` виден только сеансу HypeDE, поэтому
обычный GNOME не знает ни режима hypede, ни компонентов его оболочки.
Сторонние расширения GNOME в сеанс HypeDE не попадают (`guard.js`), а
программы автозапуска можно выключить только для HypeDE — их юниты
`app-*@autostart.service` проверяет `hypede-autostart-filter`.

`XDG_CURRENT_DESKTOP` в сеансе — `HypeDE:GNOME`. Благодаря этому
значения по умолчанию из `90_hypede.gschema.override` (секции с суффиксом
`:HypeDE`) действуют только внутри HypeDE, а порталы и приложения,
которые ищут «GNOME», по-прежнему его находят.

## Оболочка: расширение `hypede-shell`

| Модуль | Что делает |
|---|---|
| `shelf.js` | Полка: переносит ячейки панели GNOME (`_leftBox`, `_rightBox`) в свой контейнер с раскладкой вдоль любого края экрана, ставит `panelBox` к этому краю (перехватывает `LayoutManager._updateBoxes`), разворачивает меню индикаторов от края, добавляет значки приложений с перетаскиванием, дату и время в трей, автоскрытие, кнопки «Выключить/Перезагрузить» на экране блокировки. Кнопка шестерёнки в быстрых настройках открывает «Настройки» HypeDE. |
| `launcher.js` | Кнопка-кольцо и лаунчер («пузырь» или на весь экран) — это `PanelMenu.Button` с собственным содержимым меню, поэтому клавиатура, Escape и клики мимо работают как у всех меню GNOME. |
| `lockscreen.js` | Оформление экрана разблокировки GNOME: волны при блокировке, часы, карточки, анимации появления поля пароля и разблокировки. Проверку пароля делает сам GNOME. |
| `windows.js` | Мягкие анимации открытия, закрытия и сворачивания окон. |
| `style.js` | Настраиваемые стили (прозрачность, скругления, размеры) — небольшой CSS, собираемый на лету, и скорость анимаций. |
| `guard.js` | Не пускает в сеанс HypeDE расширения обычного GNOME и держит компоненты HypeDE включёнными на экране блокировки. |
| `quicksettings.js` | Быстрые настройки в три колонки: переключатели GNOME становятся круглыми кнопками с подписью. |
| `corners.js` | Скругление углов шейдером и тень для окон, которые их не рисуют (Qt, Firefox, окна без рамки). |
| `locker.js` | Экран блокировки без GDM: создаёт `ScreenShield` GNOME и проверяет пароль через `hypede-auth` (PAM). |
| `assistant.js` | Ставит окно ИИ-помощника панелью у правого края и даёт лаунчеру кнопку «Спросить». |
| `greeting.js` | Приветствие при входе: волны, текст по буквам, звуки. |
| `filesearch.js` | Список имён файлов домашней папки для поиска в лаунчере (без индексатора GNOME). |
| `calculator.js` | Разбор арифметики рекурсивным спуском (без `eval`). |
| `recent.js` | Чтение `recently-used.xbel` для «Продолжить с того же места». |
| `overview.js` | Super → лаунчер, обзор без дока и строки поиска, старт сеанса сразу на рабочем столе. |
| `notifications.js` | Баннеры уведомлений в правом нижнем углу, появление снизу вверх. |

Почему ячейки панели GNOME, а не свои индикаторы: панель GNOME уже держит
меню всех системных индикаторов (сеть, звук, Bluetooth, питание, запись
экрана) и режимы сеанса, а `panelBox` резервирует место под окна (strut) и
прячется в полноэкранном режиме. Раскладку панели GNOME (`vfunc_allocate`)
поменять нельзя — поэтому ячейки переезжают в контейнер HypeDE, который
умеет и горизонтальную, и вертикальную раскладку.

Стили генерируются `tools/gen-shell-css.py` из одного шаблона в две палитры
(светлую и тёмную); GNOME сам выбирает файл по системной схеме. Цвет
акцента берётся из `-st-accent-color`, поэтому выбор акцента в «Настройках»
перекрашивает и полку.

## «Настройки»: модули KDE в интерфейсе Chrome OS

```
MainWindow (QWidget, без системной рамки)
 ├─ QQuickWidget — весь интерфейс на QML: заголовок с поиском, меню, карточки
 └─ контейнер модуля (QWidget) — лежит поверх QML ровно в «окне» карточки
      └─ KCModuleLoader::loadModule(...) — модуль KDE, как в kcmshell6
```

* `KcmHost` загружает модуль по id (`kcm_pulseaudio`, `kcm_networkmanagement`…),
  ищет его во всех каталогах Plasma 6 и кладёт его виджет в контейнер.
  `KCModuleLoader` одинаково работает и с QML-модулями, и со старыми на
  виджетах, поэтому встраиваются оба вида.
* `GSettingsObject` — мост QML ↔ GSettings для разделов, которыми в
  сеансе управляет GNOME.
* `System` — D-Bus: power-profiles-daemon, NetworkManager (Wi-Fi),
  timedated (синхронизация времени), версия GNOME Shell.
* Палитра модулей KDE берётся из цветовых схем `HypeDE Light/Dark`
  (светлые фоны и синий акцент Chrome OS) и переключается вместе с
  темой GNOME.
* Каталог разделов (`qml/Catalog.qml`) — декларативный: строка описывается
  объектом `{type, schema, key, …}`. По этому же каталогу работает поиск.

## «Файлы»

```
Adw.OverlaySplitView
 ├─ Sidebar           места, закладки GTK, устройства (Gio.VolumeMonitor)
 └─ ToolbarView
     ├─ HeaderBar     назад/вперёд, PathBar (крошки ↔ поле адреса), вид, поиск
     ├─ Adw.TabBar    вкладки (COSMIC)
     ├─ SearchBar     рекурсивный поиск в фоне
     └─ Adw.TabView → FolderView (на каждую вкладку)  +  DetailsPane (COSMIC)
```

`FolderView` собран из готовых моделей GTK: `Gtk.DirectoryList` (чтение
каталога асинхронно, слежение за изменениями) → фильтр скрытых →
сортировка «папки сначала» → `Gtk.MultiSelection`, и две вьюхи на одной
модели — `Gtk.GridView` и `Gtk.ColumnView`. Файловые операции идут в
фоновых потоках через Gio (понимают `trash://`, `sftp://`, `smb://`), а
результат сообщается тостом с кнопкой «Отменить».

## ИИ-помощник

`hypede-assistant` (Python, GTK 4, WebKitGTK 6) открывает сайт выбранного
провайдера во встроенном браузере. Вход — на самом сайте, куки хранятся в
`~/.local/share/hypede/assistant/<провайдер>`. Вопрос и файлы, переданные
кнопкой «Спросить», вписываются в поле ввода чата скриптом на странице
(поле ищется по виду, отправляет вопрос сам пользователь). Ссылки на другие
сайты открываются в обычном браузере, запросы камеры, микрофона и
местоположения отклоняются.

## Значки и звуки

Тема значков `HypeDE` (`data/icons/HypeDE`, собирается `tools/gen-icons.py`)
кладёт Material Symbols под стандартными символьными именами и наследует
Adwaita. Значки мест, дисков и типов файлов в неё не входят: GTK 4 ищет
значок сначала во всей теме, и символьная папка заменила бы цветную.

Звуковая тема `hypede` (`data/sounds/hypede`) синтезируется
`tools/gen-sounds.py` из синусоид и шума, записей в ней нет.
